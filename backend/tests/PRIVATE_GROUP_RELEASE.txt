Access boundary
---------------
backend/firebase.private.json points the existing default Hosting site at an
empty directory containing only an ignored .gitkeep. Every application route
rewrites to the privateSite Gen 2 Function in europe-west3. No HTML, JS, fonts,
logos, downloads or sitemap are uploaded to Hosting's public static directory.
The protected bundle resides in the Function deployment, with an exact path and
SHA-256 manifest. Authorized bytes must match; arbitrary Function source,
environment, review and manifest paths are not served. Source/storage/build
artifacts must retain project IAM restrictions; never attach the bundle to a
public GitHub build artifact or release.

Anonymous users receive only the small Arabic login form. Page/asset requests
redirect to it; API requests return 401. The direct Function URL requires the
same session. Provider-reserved /__/ Firebase infrastructure URLs are outside
our rewrite; they contain no packaged website or prayer records. External
MAWAQIT and Quran/library sources are not made private by our shared code.

All application responses use private/no-store, Vary: Cookie, noindex, nosniff,
frame denial and a restrictive form-action/base/object policy. Firebase Hosting
forwards the __session cookie to the Function. A cryptographically random opaque
token is Secure, HttpOnly, SameSite=Lax, host-only, Path=/, Max-Age=90 days. Only
its hash, issue/expiry times and revocation epoch are stored server-side. Every
protected request checks that record; JavaScript never receives the cookie/code.
There are no user accounts, Firebase Auth users or individual passwords.

Every mutating request, including login/logout, requires the exact HTTPS Origin.
Referrer-Policy is same-origin: no-referrer suppressed the Origin of native form
submissions in WebKit and was corrected after an actual failed browser test.
Cross-origin forms/API requests fail 403; the gateway supplies no CORS allowance.

The 16-symbol random shared code has 80 bits of entropy. The backend stores a
salted scrypt verifier in Secret Manager, never the clear code. Persistent global
login budgets are 60/hour and 200/day before scrypt; maximum 256 active sessions.
No failed code or IP is stored by application code. This intentionally simple
global budget can temporarily deny new logins if abused; it does not block
already-valid sessions. It is not a complete DDoS or billing cap.

Logout revokes the server record, so a copied old cookie also fails. Rotating
both verifier and epoch, then redeploying the Function, revokes old sessions.
Expired sessions are pruned hourly and during login. A first-party persistent
cookie supports Safari, but device deletion/private browsing can still require
the code again. Already-open pages and authorized print/download copies cannot
be remotely erased; the client rechecks on return to a tab and reloads BFCache.
Possession of one shared code grants group access; it does not verify identity
or allow selectively revoking one colleague who still knows the code.

Prayer coordination and isolation
---------------------------------
The relative same-origin endpoint /nur-und-huda/api uses the named service:
create, organizer as participant one, Arabic/Latin first names, optional note,
multiple gatherings for a prayer, join/leave, browser duplicate protection and
organizer-only cancellation. Ownership bearer capabilities remain independent
of the group session, invisible in the UI and never placed in URLs.

privateAccess/state: hashed sessions and aggregate login budgets only.
prayerService/group: private group's named gatherings and transient protection.
prayerService/state: unchanged restricted staging contract/data.
prayerService/public: old public-preparation state, never used by this site.
No staging data migration or public API activation is performed. Firestore
client rules remain deny-all. The runtime service account still needs only
database-scoped datastore.user plus accessor on the one group secret.

Gatherings disappear at their chosen start time. Hourly cleanup removes expired
names, notes and ownership records; leave removes the name immediately. Cancel
clears names/notes. Temporary replay/rate state follows existing <=27h cleanup.
First name remains on the device until changed/deleted; ownership capability
expires after 26h without an action. No attendance history is introduced.
The privacy page explains these durations, shared-code access, provider logging,
external MAWAQIT, locally saved preferences and copies, and independence from the
hospital. It does not invent operator details or declare legal compliance.

privateSite; verify all protected URLs fail closed. Keep cleanup running.
Do not roll Hosting back to a version containing static unprotected pages or
turn on publicPrayerApi as a workaround. Roll back Function and empty-Hosting
configuration as a matched tested pair. Never disable billing/delete Firestore.

For code rotation, preserve the old local packet as an audit artifact, create a
fresh random code/salt/digest/epoch in a new private packet, upload a new version

the new code works, then disable the superseded secret version after rollback
considerations. The key helper refuses to overwrite an existing packet; no live
rotation or automatic secret pruning has been performed.
